# Claude Code : ce que TermF doit gérer (inventaire de référence)

> Relevé le 2026-11-21 dans la documentation officielle (code.claude.com), pour Claude Code 2.1.330 (la doc cite des versions jusqu'à ~2.1.305). « (non vérifié) » : absent des pages lues. Avant de coder une tranche, revérifier la page citée et `claude --help` sur la version installée. Tous les chemins `~/.claude*` (y compris `~/.claude.json` et le trousseau) suivent `$CLAUDE_CONFIG_DIR` s'il est défini.

## Règles pour une app externe

- Écrire les fichiers de réglages **atomiquement** (temporaire + rename), en JSON strict ; un JSON invalide provoque une erreur de réglages au démarrage suivant.
- Ne pas éditer `~/.claude.json` pendant que Claude Code tourne : passer par `claude mcp …` / `claude plugin …`. Ne jamais toucher `installed_plugins.json`, `.credentials.json` ni les jetons OAuth des MCP.
- **Ne pas parser les transcripts JSONL ni `~/.claude/jobs/`** : format interne, change entre versions. Sources stables : JSON de la statusline, `claude -p --output-format json|stream-json`, `claude agents --json`, `claude auth status`, `transcript_path` des hooks (comme pointeur).
- Une session lancée par TermF reçoit ses surcharges par `--settings <fichier-ou-json>` (portée session, n'écrit rien chez l'utilisateur), `--plugin-dir`, `--mcp-config`, `--append-system-prompt-file`.

## Ce qu'une app externe ne peut pas faire

1. Lister, créer ou annuler les boucles et cron d'une session depuis l'extérieur.
2. Gérer les jetons API des routines cloud ou supprimer une routine depuis la CLI (web seulement).
3. Lire un flux d'usage stable hors statusline et `-p`.
4. Répondre aux demandes de permission d'une session interactive (seulement `--permission-prompt-tool`, hooks `PermissionRequest`).
5. Créer skills, agents, styles ou règles par une commande : on écrit les fichiers.
6. Modifier la configuration côté claude.ai (réglages gérés par le serveur, connecteurs, politique d'organisation).

## Évals de plugins et serveurs de langage

> Relevé le 2026-11-22 dans /docs/en/plugin-evals, /docs/en/plugins/components (« LSP servers »), /docs/en/plugins/manifest-reference (`lspServers`), /docs/en/plugins/code-intelligence, et la marketplace `anthropics/claude-plugins-official` ; essayé avec Claude Code 2.1.330.

- **`claude plugin eval [cible]`** (Claude Code ≥ 2.1.269 ; git ≥ 2.31 s'il est installé, vérifié depuis 2.1.283) : un cas = `evals/<cas>/` avec `prompt.md` (frontmatter : `schema_version`, `name`, `description`, `tags`, `plugins`, `runs`, `expected_outcome`, `model`, `max_turns` 10 par défaut, `timeout_seconds` 300, `allowed_tools`, `append_system_prompt`, `env` en `EVAL_*` ; une clé inconnue est une erreur) et / ou `case.yaml` (`schema_version: "1.1"`, `name`, `context.scaffold_script|history_file|add_dirs`, `execution.*`, `graders`), et `graders/<nom>.md` : `regex` (`pattern` JavaScript, `flags`, `match: not_contains|count:N`, `target`), `tool_used` (`tool`, `input_match`, `min`, `max` ; `min: 0, max: 0` = jamais), `tool_order`, `file_exists`, `llm` (corps = critères, `focus`, 2 votes sur 3), `baseline` ; `weight`, `arm`. Cible : `last_message`, `trace`, `files`, `{ source: file, path }`, `mock_calls`. Pas de correcteur en code.
- **Isolation** : chaque run est un `claude -p` avec `HOME`, config et dossier de travail temporaires et le seul plugin testé (ni réglages, ni `CLAUDE.md`, ni MCP, ni autres plugins) ; outils en lecture seule seulement, le reste par `--allow-tools` (Bash exige le bac à sable : pas sous Windows natif) ; `scaffold_script` seulement avec `--scaffold` ; outil Artifact coupé ; l'agent ne voit pas le dossier des évals.
- **Options utiles** : `--runs` (3), `--model`, `--judge-model` (par défaut le modèle des tâches de fond), `--ablation none|with-without` (sans plugin en plus : `Δ`), `--threshold` (1.0), `--max-cost-usd`, `--trust-plugin` (CI), `--json [chemin]`, `--output-dir`, `--no-publish`, `--case`, `--tag`, `--scaffold`, `--keep-temp`. Sortie 0, 1 (cas sous le seuil, cas illisible, erreur d'API), 2 (plafond de coût, identifiants refusés), 130, 143 ; `aggregate-result.json` en `schemaVersion: 1` (`costUsd`, `aggregates.casesPassed|casesTotal|overallScore`, `cases[].aggregates.score`, `cases[].arms.with[].error`). Un `tool_used: Skill` ne compte pas dans le score en mode deux bras.
- **Dans un worktree d'agent** : Claude Code n'y est pour rien (un plugin dans un worktree git s'évalue normalement, essayé le 2026-11-22) ; c'est la garde des sous-agents isolés en worktree qui refuse toute commande où `eval` est un mot (« runs a string through eval »). `pnpm evals` (dans `app/`) l'évite et construit de toute façon un plugin temporaire hors du dépôt, la bibliothèque n'ayant pas la forme d'un plugin.
- **Serveurs de langage** : `.lsp.json` à la racine du plugin (ou la clé `lspServers` du manifeste), une table nom → configuration, sans enveloppe : `command` (requis, binaire cherché dans le `PATH`, sans espace), `extensionToLanguage` (requis, au moins une extension commençant par `.`), `args`, `transport` (`stdio`), `env`, `initializationOptions`, `settings`, `workspaceFolder`, `startupTimeout`, `shutdownTimeout`, `requestTimeout` (≥ 2.1.288, 60 s par défaut), `restartOnCrash`, `maxRestarts`, `diagnostics`. Objet strict : une clé inconnue fait ignorer tout le fichier (`Invalid LSP server config for ".lsp.json"` dans `/plugin`, onglet Errors) ; `claude plugin validate` ne le lit pas. Binaire absent : `Executable not found in $PATH` (onglet Errors) ; deux serveurs pour une extension : le premier enregistré la garde, l'autre est signalé (`LSP server "<nom>" is not used for <ext> files`). Le serveur démarre à la première modification d'un fichier de son extension ; Claude reçoit ses diagnostics après chaque modification et un outil `LSP` en lecture. Pas dans les sessions cloud. Version minimale de `.lsp.json` : (non vérifié), la doc n'en cite pas. Plugins officiels `<langage>-lsp@claude-plugins-official` (clangd, csharp-ls, gopls, jdtls, kotlin-lsp, lua-language-server, intelephense, pyright-langserver, ruby-lsp, rust-analyzer, sourcekit-lsp, typescript-language-server) : TermF reprend leurs configurations.
