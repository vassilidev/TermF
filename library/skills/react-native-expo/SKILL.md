# React Native and Expo

Expo publishes official skills in [expo/skills](https://github.com/expo/skills) (MIT: `expo-router`, `expo-upgrade`, `expo-module`, `expo-dev-client`, `eas-update`…), installed in Claude Code with `claude plugin install expo@claude-plugins-official`. When one is loaded in the session, follow it for its topic; this skill keeps the version facts, the gotchas and the checks.

1. Read the versions in the lockfile: `expo` gives the SDK (its major: `58.0.x` is SDK 58), then `react-native` and `react`. Each SDK pins one React Native and one React (table at `https://docs.expo.dev/versions/latest/`): SDK 58 runs React Native 0.88 and React 19.3.0, SDK 57 runs 0.86 and 19.2.3, SDK 56 runs 0.85 and 19.2.3. No `expo` dependency means React Native without Expo: read `react-native` only. Then check whether `ios/` and `android/` are listed in `.gitignore` (generated by prebuild: Continuous Native Generation) or committed (edited by hand). Done when you can name the SDK, React Native, React and which native setup the project uses.
2. Open the docs of that version: `https://docs.expo.dev/llms.txt` (every page also exists as Markdown with `.md`), the SDK reference at `https://docs.expo.dev/versions/v<SDK>.0.0/`, and `https://reactnative.dev/llms.txt` for React Native APIs (`https://reactnative.dev/docs/<version>/…` for an older release). Before an SDK upgrade, read that SDK's post on `https://expo.dev/changelog`. Done when the page for the task is open.
3. Add or change a package with `npx expo install <package>`, through the project's package manager (`pnpm expo install`, `yarn expo install`, `bun expo install`; flags for the package manager go after `--`, as in `-- -D`), because it picks the version that matches the SDK. `react-native` and `react` move only with the SDK (`npx expo install expo@^<SDK>.0.0 --fix`). Without Expo, change `react-native` and `react` together and apply the native diff from `https://react-native-community.github.io/upgrade-helper/`. Done when `npx expo install --check` reports nothing to fix.
4. Change native settings where they live. With Continuous Native Generation, `ios/` and `android/` are build output: write the change in the app config (`app.json` or `app.config.ts`: identifiers, permissions text, `plugins` with their options) or in a config plugin (a local `plugins/with<Feature>.js` built on `withInfoPlist`, `withAndroidManifest`…, listed in `plugins`), then run `npx expo prebuild --clean` and read the generated diff. With committed native folders, edit them and run `npx pod-install` after an iOS dependency change. Done when the change survives `npx expo prebuild --clean`, or is in the committed native project.
5. Write screens the way the project routes. With Expo Router, every file under `src/app/` (or `app/`) is a route, `_layout.tsx` files hold navigators and providers, and folders in parentheses group routes without changing the URL; components, hooks and constants live outside that folder, or they become routes. Done when the route renders in a development build.
6. Run the app in a development build (`npx expo run:ios`, `npx expo run:android`, or the project's development EAS profile) as soon as the app has a native module that Expo Go lacks; an Expo Go release supports one SDK only. Done when the screen of the task runs on a simulator or emulator, or your report says none was available.
7. Test with the project's runner from the acceptance criteria (skill `tests-from-criteria`): component tests that query by role, label or text as a user would. A flow on a simulator or emulator belongs to the skill `mobile-testing`. Done when the new test fails without your change.
8. Run the commands of `## Verify` and put each one with its result in your report. Done when they pass, or the failure is reported with its output.

## Gotchas

- New Architecture only since SDK 55 (React Native 0.82 removed the opt-out): `newArchEnabled` is ignored, delete it from the app config. A library without New Architecture support cannot be used; `npx expo-doctor@latest` checks the dependencies against React Native Directory.
- SDK 58 (October 2026), what models miss:
  - Node 22.13+ on the 22 line, 24.3+ on 24, or 26+; odd Node releases are unsupported.
  - iOS uses the scene lifecycle: prebuild generates `SceneDelegate.swift`, and a customized `AppDelegate.swift` follows the scene migration guide.
  - Deep imports from `react-native/Libraries/*` are type errors (Strict TypeScript API, the default since React Native 0.87).
  - `InteractionManager`, the `Touchable` root export and the `animated` prop of `Modal` are gone.
  - R8 runs on Android release builds: a library that relies on reflection needs its keep rules.
  - `File.write()` of `expo-file-system` is async (`File.writeSync()` keeps the old behaviour).
  - The CLI sets `NODE_ENV` per command, which changes the `.env` files it loads.
  - Expo Router's navigation core changed: `withLayoutContext` is deprecated for `integrateWithRouter`; custom navigators and `expo-router/react-navigation` imports may need changes.
- `npx expo prebuild` without `--clean` layers onto the existing native files, and some config plugins are not idempotent: regenerate with `--clean`. EAS Build runs prebuild when the native folders are absent, so a hand edit in a generated folder never reaches a cloud build.
- EAS Update ships JavaScript and assets only. A change that adds or updates native code needs a new build, and its `runtimeVersion` must change too (policy `fingerprint` or `appVersion` in the app config), else installed builds download an update that calls native code they lack. Publishing is `eas update --channel <channel> --message "<text>" --environment <environment>`; `--environment` is required since SDK 55.
- Upgrade one SDK at a time: `npx expo install expo@^<next>.0.0 --fix`, `npx expo-doctor@latest`, the breaking changes of the SDK post, delete generated `ios/` and `android/`, then a new development build.

## Verify

- The project's scripts first (`lint`, `typecheck`, `test` in `package.json`, the CI workflow).
- `npx expo install --check`, `npx expo-doctor@latest`, `npx tsc --noEmit` when the app is in TypeScript, `npx expo lint`.
- After a native change with Continuous Native Generation: `npx expo prebuild --clean`, then `npx expo run:ios` or `npx expo run:android` when a simulator or emulator is available; otherwise say it was not run.

## Security

- `EXPO_PUBLIC_` variables are inlined in plain text into the JavaScript bundle: no private key or server secret there. A secret stays on a server the app calls, or in EAS environment variables used at build time.
- Tokens and credentials go in `expo-secure-store` (Keychain on iOS, Keystore-encrypted on Android), never in AsyncStorage or a plain file.
- Every Expo Router screen can be opened by a deep link: validate route params and check the session in the screen or its layout, never only in the screen that usually links to it.
- `eas build`, `eas update` and `eas submit` act outside the repository (Expo's servers, installed apps, the stores): run them only when the user asked for that exact action, otherwise report `blocked` with the command.

## References

- Before an SDK upgrade, read the SDK's post on `https://expo.dev/changelog` and, when installed, the official `expo-upgrade` skill.
- Read `https://docs.expo.dev/config-plugins/mods.md` and `https://docs.expo.dev/config-plugins/dangerous-mods.md` before writing a config plugin that edits a native file no `with…` helper covers.
- Read `https://docs.expo.dev/eas-update/runtime-versions.md` before changing `runtimeVersion` or an update channel.
